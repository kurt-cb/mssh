# adhoc-learnings.md

Accumulative knowledge from adhoc-testing sessions. **Read this first
before starting a new round** — it tells you what's already known
weak, where to probe, and what assumptions cost time last session.

If you're an LLM agent doing autonomous-explorer testing, this is your
field guide. Append findings; don't rewrite. New sessions get a new
trailing section dated YYYY-MM-DD.

---

## Architecture quick-glance

Three processes per server, two on the CA host:

```
mssh client ──TLS+JSON header──> msshd (gateway) ──asyncssh──> inner sshd ──> user shell
                                       │
                                       └─https mTLS─> mssh-ca (Flask)
```

The mssh client is **not** an SSH client. It speaks a small custom
protocol (`PROTOCOL_VERSION=1`):

1. TLS handshake (mTLS).
2. JSON header line: `{"v":1,"command":...,"interactive":...,"term":..,...}`.
3. JSON ack: `{"v":1,"ok":<bool>,"reason":...}`.
4. After ack: **raw bytes both ways, stdout+stderr merged on the return**.

Everything past the ack is a dumb byte pump. This is the source of
most bugs.

## Known weak spots (probe these first)

### The byte pump after the ack

Five of the six bugs found in the 2026-05-19 session live here. The
protocol carries no typed frames after the ack — no exit-status, no
EOF, no stderr separation, no deny-reason. Anything you can do with
SSH that uses those features will silently misbehave through mssh.

**Quick probes** (each <5 seconds):
- `mssh user@host -- false ; echo $?` — should be 1, will be 0.
- `mssh user@host -- 'head -c 100 /dev/urandom' | wc -c` — should be
  100, will be 0 if the `encoding=None` fix is regressed.
- `echo x | mssh user@host -- cat` — should print `x` and exit, will
  print `x` then hang on stdin EOF.
- `mssh user@unauthorized -- whoami` — should print actionable deny,
  prints `mssh: server closed before sending ack`.

### Connect-timeout

mssh has no client-side connect timeout. Pointing it at an unrouted
IP hangs until the OS gives up (~2 min). Probe with `192.0.2.1`
(RFC 5737 docs prefix).

### Inner-sshd / asyncssh encoding

Bug #5 demonstrated asyncssh's default `encoding='utf-8'` on
`create_session` silently kills the channel on non-UTF-8 bytes. The
fix (`encoding=None`) is now in. **Any future code that touches
asyncssh sessions should explicitly set `encoding=None`** unless
there's a deliberate reason to enable string mode.

### Flip scripts on per-connection mode

User reported `flip_to_per_connection` reverts on all servers in
their session. The CA's audit log records the test as denied? Or
something else? Not investigated yet. Flag for next session.

## Things that DO work reliably (don't waste time re-checking)

- Phase 0 — vanilla ssh user@host
- Phase 1 — ssh user@host:2200 (msshd fallback proxy)
- Phase 2 — mssh user@host (cert + CA + inner sshd) **for text-only,
  no-stdin commands**
- Concurrent sessions (3-5 parallel mssh calls all complete)
- Authz cache (second connection from same principal is ~200 ms,
  doesn't re-call the CA)
- Deny enforcement at the CA (audit log is correct + complete)
- 5-second sleep within a session (no premature timeout)
- mssh against the wrong port (clear error: "Connection refused")

These can be smoke-checked once per session if at all.

## Lab quirks worth knowing

- **Alpine container** uses OpenRC, not systemd. `systemctl
  restart msshd` works on Ubuntu containers but fails on the eng
  container with "Command not found." Manual kill+restart needed.
  The flip scripts handle this via `_msshd_restart_cmd(s)` per server;
  ad-hoc operations don't.
- **adhoc-env.sh is regenerated by the test framework** every time
  the lab is provisioned. Container IPs change. The
  `mssh_as`/`ssh_as`/`flip_to_*` helpers are stable in shape but
  point at fresh containers.
- **Setup time:** 7–10 min depending on lxd caching. First-ever run
  takes longer (build base images). Subsequent runs reuse the
  `mssh-ubuntu-fixed` / `mssh-alpine-fixed` aliases.
- **Source on each container** is at `/app/src/mssh/...` — same shape
  as the host repo's `python/src/mssh/`. To test a code change without
  re-provisioning: `lxc file push <host-path> <container>/<path>` then
  `systemctl restart msshd` (or manual restart on Alpine).
- **CA audit log** is at `/var/log/mssh/audit.jsonl` on the CA
  container. Tail it for the CA-side view when client errors are
  cryptic.
- **adhoc-keys/** on the host persists across runs. User certs, keys,
  and CA cert live there.

## For Claude-as-tester (when this becomes automated)

The user-side flows that gave good signal in 2026-05-19:

| Probe | Catches |
|-------|---------|
| `mssh user@auth-server -- whoami` | Happy-path break |
| `mssh user@unauth-server -- whoami` | Auth + deny propagation |
| `mssh user@host -- false` (check $?) | Exit-code propagation |
| `mssh user@host -- 'head -c N /dev/urandom' \| wc -c` | Binary fidelity |
| `echo x \| mssh user@host -- cat` | stdin data + EOF |
| `mssh user@host -- 'echo o; echo e >&2'` (split fds) | stderr routing |
| `mssh user@host -- 'sleep 5; echo done'` | Long-running session |
| `mssh user@host -- 'head -c 1G /dev/zero' \| wc -c` | Large stream |
| 3× `mssh user@host -- whoami` in parallel | Concurrency |
| `mssh user@unrouted-ip:2200 -- whoami` | Connect timeout |
| `mssh user@host:wrong-port -- whoami` | Error quality |

Order them happy-path → semantics → stress. Stop at the first
session-rebooting hang; document residuals.

**Tester budget:** keep each probe time-boxed at 10–15 seconds. The
mssh client should never reasonably take longer than that for these
probes, so if it does, that's itself a bug.

**Cleanup:** if a probe leaves a hung `python3 -m mssh.client` process,
`pkill -f mssh.client` is safe between probes. The lab's msshd
sessions clean up after their inner sshd closes.

## Open architectural questions surfaced during exploration

These don't need an answer yet; they shape future-ideas roadmap.

1. **Should the post-ack stream be framed?** Today: raw byte pump.
   Adding `{stdin, stdout, stderr, exit, signal, deny}` types would
   close Bugs #1, #2, #3-EOF, #4 in one protocol change. Cost: bumps
   protocol to v1.1, requires msshd + client coordinated upgrade.
2. **Should `mssh` speak SSH instead of a custom protocol?** Then
   asyncssh handles all the channel semantics for free. Cost: client
   becomes ~3x bigger, mTLS-over-SSH composability questions.
3. **How does fallback differ from enforce-with-permissive-policy?**
   Worth thinking about during the protocol redesign — maybe
   "fallback" and "enforce" are the same code path with a CA-skip
   flag.

## Appended 2026-05-19 round 2 (lab claude-t1Fx)

### Deployment gotcha: `__pycache__/` survives `lxc file push`

If you push a `.py` to a container and `systemctl restart` the service,
**Python may load the stale `.pyc`** instead of your updated `.py`.
Confirmed during the Bug #8 fix on the CA container: the fix to
`templates.py` did not take effect until `find /app/src -name
__pycache__ -exec rm -rf {} +` ran before the restart.

Reason hypothesis: `lxc file push` may not preserve the .py's mtime
with the precision Python's import machinery uses to invalidate
.pyc files. Or LXC's filesystem layer reports a different mtime to
container-side calls vs host-side stats.

**Workaround for code-push iterations on a running lab:**
```bash
for c in <containers...>; do
    lxc file push <host-path>.py "$c"/<container-path>.py
    lxc exec "$c" -- find /app/src -name __pycache__ -exec rm -rf {} +
    lxc exec "$c" -- systemctl restart <service>
done
```

This is also a recommendation for the eventual `install_mssh.sh`
packaging path: set `PYTHONDONTWRITEBYTECODE=1` in the systemd unit
to make the dev workflow safer.

### Two distinct sshd_config templates exist

`config/sshd_config.template` — used by the **long-lived** inner sshd
([msshd/inner.py:217-224](../python/src/mssh/msshd/inner.py#L217-L224)).
Rendered ONCE at msshd boot.

`mssh.ca.templates.BUILTIN_OPENSSH_TEMPLATE` — used by the
**per-connection** inner sshd path
([msshd/inner.py:402-420](../python/src/mssh/msshd/inner.py#L402-L420)).
Rendered by the CA on every authorize call.

Until 2026-05-19 these had diverged silently: the long-lived template
allowed `ssh-ed25519-cert-v01@openssh.com`; the CA's built-in didn't.
The per-connection path was broken from the moment it landed but
silently fell back to long-lived because the flip script reverts on
verify failure.

**Implication:** Whenever you touch one of these templates, audit
the other to see if the same change is needed. Any directive that
affects auth (Pubkey*, Trusted*, AuthenticationMethods,
PermitRootLogin) must be checked in both files.

Even better: have a single canonical template with a documented diff
between the two contexts. This is design work, not a quick fix —
flag for a future round.

### mssh-admin is NOT installed in the lab

Operators following docs/operations.md will hit `mssh-admin: command
not found` on the CA container. The lab only installs
`/usr/local/bin/mssh` (a shim around `python3 -m mssh.client`). The
test framework's own admin actions go through `mssh.admin.client.CAClient`
directly (Python API), not the CLI.

**For testing admin functions in this round:**
```bash
ADMIN() {
    lxc exec claude-t1Fx-adhoc-ca -- bash -c "PYTHONPATH=/app/src python3 -m mssh.admin.main \
        --ca-url https://10.26.244.215:8443 \
        --admin-cert /etc/mssh/ca/bootstrap-admin-cert.pem \
        --admin-key /etc/mssh/ca/bootstrap-admin-key.pem \
        --ca-cert /etc/mssh/ca/tls-ca-cert.pem $*"
}
ADMIN status
ADMIN 'audit --decision denied --limit 5'
```

Should ship as a `/usr/local/bin/mssh-admin` shim, same shape as the
existing `/usr/local/bin/mssh`.


### Banner customization is invisible to mssh users

`banner.template_path` and `values` substitution works at the inner
sshd layer. The custom banner file is written. But the mssh client
never reads it — the outer protocol carries no banner channel and
the inner-sshd's pre-auth banner is consumed by msshd (which is the
SSH client), never relayed to the mssh user.

**For operators:** customize whatever you like; users will not see
it via `mssh`. This is mostly a documentation gap — the banner
feature reads like end-user-facing but isn't.
