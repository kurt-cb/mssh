# adhoc-lab ansible project

The single source of truth for the lab's ansible setup. Everything in
this directory is the operator's working set — add tasks, edit
variables, drop in new task files, all of it lives here in git.

## Three identical directories

When the adhoc lab spins up, the test harness creates two copies of
this directory:

```
python/tests/ansible-project/          ← THIS DIRECTORY (committed)
                                         source of truth
              │
              │  test_setup_only_msshd.py::_write_ansible_project()
              │  copies every file verbatim, then overwrites hosts.ini
              │  with one rendered from the live lab.
              ▼
<invocation_cwd>/ansible-project/      ← rendered host-side copy
                                         where you run ansible from
              │
              │  test_setup_only_msshd.py::_setup_ansible_on_ca()
              │  pushes every file verbatim, including hosts.ini and
              │  the generated keypair, to the CA.
              ▼
ca:/root/ansible-project/              ← pushed CA-side copy
                                         where you can also run ansible
```

All three directories end up with the same files. **Two files are
auto-generated**, never edited by hand:

| File                  | Where it comes from                                                                                  |
|-----------------------|------------------------------------------------------------------------------------------------------|
| `hosts.ini`           | Rendered by the test from the live lab's container names + bridged IPs. The committed copy is a placeholder example. |
| `ansible_id_ed25519`  | Generated by the test on first run, into the host-side copy. Mode 0600. Pushed to the CA at the same mode. The `.pub` half ends up in every container's `/root/.ssh/authorized_keys`. |

Everything else (`ansible.cfg`, `site.yml`, `variables.yml`,
`task_*.yml`, `README.md`) is copied verbatim. **Edit files here
and re-run the test to push them**, or edit the rendered copy
directly for quick experimentation knowing the next setup wipes it.

## Layout

| File                       | Purpose                                                  |
|----------------------------|----------------------------------------------------------|
| `ansible.cfg`              | Inventory, host-key-check off, pipelining                |
| `hosts.ini`                | Inventory (placeholder; auto-rendered at lab setup)      |
| `site.yml`                 | Top-level playbook; pulls in every `task*.yml`           |
| `variables.yml`            | Proxy IP/port + deployment values                        |
| `task_squid.yml`           | Point each host at the squid proxy (tag: `squid`)        |
| `task_upgrade_asyncssh.yml`| Fix Ubuntu 22.04 asyncssh ≤2.5 bug (tag: `upgrade_asyncssh`) |
| `ansible_id_ed25519`       | Private key — auto-generated at lab setup                |

## Invocation

**Task files (`task_*.yml`) are NOT standalone playbooks.** They're
task lists that `site.yml` pulls in via `include_tasks`. Running
them directly fails with `'ansible.builtin.lineinfile' is not a
valid attribute for a Play`.

Always invoke through `site.yml`:

```sh
cd ansible-project              # or /root/ansible-project on the CA

ansible all -m ping             # smoke-test connectivity
ansible-playbook site.yml       # run every task on proxy_clients

# Subset by tag (cleaner than --limit):
ansible-playbook site.yml --tags squid
ansible-playbook site.yml --tags upgrade_asyncssh

# Subset by host group:
ansible-playbook site.yml --limit ubuntu_servers
```

`proxy_clients` is a `children` group rolling up
`ubuntu_servers + alpine_servers + debian + fedora_servers`, so
`ansible-playbook site.yml` hits every lab container by default.

## Adding tasks

Drop a new `task_<name>.yml` here. `site.yml`'s glob picks it up
automatically on the next run. Tag your tasks so operators can run
them selectively:

```yaml
- name: "myfeature: do the thing"
  ansible.builtin.command: /usr/local/bin/thing
  tags: [myfeature]
```

Then: `ansible-playbook site.yml --tags myfeature`.

Commit the new task file back to `python/tests/ansible-project/` for
permanence; otherwise the next lab re-setup wipes the rendered copy.
